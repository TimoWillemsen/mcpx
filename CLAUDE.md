# mcpx

A generic command-line client for MCP servers. Lets any shell, script or coding
agent (e.g. one that can run bash but has no native MCP support, or where native
MCP isn't allowed) list and call tools on any MCP server. Open source (MIT); keep
it vendor-neutral: no server-specific code, names or defaults.

## Stack
TypeScript, Node 20+, official @modelcontextprotocol/sdk, commander for CLI
parsing, @napi-rs/keyring for the OS keychain, zod for config validation,
vitest for tests.

## Commands
mcpx servers
mcpx tools <server>
mcpx describe <server> <tool>
mcpx call <server> <tool> [key=value... | '<json>'] [--unwrap]
mcpx login <server>
mcpx logout <server>
mcpx doctor [server] [--offline]
mcpx setup-agent <agent...> / mcpx instructions

## Requirements
- JSON on stdout when piped/captured, human-readable text on a TTY; --json or
  --text forces one, MCPX_OUTPUT=json|text sets the default. Errors go to stderr
  as JSON ({"error":{kind,message,exitCode}}), or "mcpx: <msg>" in text mode
  (decided by whether stderr is a TTY).
- Config at $MCPX_CONFIG_DIR, else $XDG_CONFIG_HOME/mcpx, else ~/.config/mcpx:
  servers.json maps name -> {command,args,env,cwd} (stdio) or
  {url,headers,oauth} (Streamable HTTP; "type":"sse" for legacy SSE).
  Accepts the {"mcpServers": {...}} wrapper and "type" fields used by other
  MCP clients. ${VAR} in env/headers/oauth.clientSecret expands from the
  environment.
- Never prompt interactively except in `login`. Commands must never hang:
  every command has a hard deadline (--timeout).
- Self-update (src/update.ts): once a day a detached `mcpx __auto-update`
  process checks release tags with `git ls-remote` (prompts disabled) and runs
  `npm install -g` for a newer vX.Y.Z tag. Never in CI, with MCPX_NO_AUTO_UPDATE,
  from a git checkout (npm link dev setups), or outside npm's global root.
- Exit codes: 0 ok, 1 tool error, 2 auth required/failed, 3 config/usage error,
  4 blocked by policy (allowedTools/readOnly)
- Tokens in OS keychain, never plaintext on disk, never in logs or output.
  Stored credentials are bound to the server URL they were issued for.
- Remote URLs must be https (plain http only for localhost). Never follow
  cross-origin redirects with credentials.
- Every `call` appended to the audit log ($MCPX_AUDIT_LOG, else audit.log next
  to servers.json; mode 0600): ts, server, tool, outcome, exitCode, durationMs.
  NEVER arguments or results.
- Guardrails are safety rails against agent mistakes, not a sandbox: an agent
  running as the user can edit the config and read the keychain. Never describe
  them as stronger than that (see README "Threat model").
- Text output and plain-text errors go through sanitizeForTerminal when written
  to a TTY (no ANSI escapes or control characters from servers); piped output is
  untouched so data isn't altered. setup-agent never writes through a
  symlink or outside the project. The plaintext test credential store is only
  allowed under the OS temp dir.
- Optional per-server config: allowedTools (names or prefix* patterns, checked
  before connecting) and readOnly (only tools annotated readOnlyHint: true;
  unannotated tools are blocked, so it fails safe). `tools` hides blocked tools.

## Status
Done: stdio, Streamable HTTP, SSE, static headers, OAuth login (dynamic
client registration or pre-registered client, PKCE, refresh, revocation),
keychain storage, guardrails (allowedTools, readOnly, audit log), agent
setup (setup-agent / instructions).

## Conventions
Small modules: config, transports, client, auth/, commands/. Tests with vitest
run the built CLI as a subprocess so exit codes and output are real; local
fixture servers live in test/fixtures (never depend on a real remote server).
Write tests for exit codes and JSON output shape.
dist/ is committed on purpose: `npm install -g github:...` can't run a build
(npm's git-dependency `prepare` is broken for global installs). Run
`npm run compile` before committing; `npm run check:dist` verifies it.
Never add a package.json script named build, prepare, prepack, install,
preinstall or postinstall: npm then "prepares" git installs with a nested
install, which breaks `npm install -g` from git (and self-update).
The plugin lives in plugins/mcpx with three manifests: .claude-plugin/plugin.json
(Claude Code; also read by Copilot CLI and VS Code), .cursor-plugin/plugin.json
(Cursor) and plugin.json (Agent Plugins standard, strict schema: keep it to
$schema/name/version/description). Marketplaces: .claude-plugin/marketplace.json
and .cursor-plugin/marketplace.json at the repo root. All manifests, the Cursor
marketplace and skills/mcpx/SKILL.md are generated by scripts/build-plugin.mjs
from package.json and src/agents.ts; don't edit them by hand. Check with `claude plugin validate .` and `claude plugin validate ./plugins/mcpx`.
The test suite must never touch the real keychain: it uses
MCPX_TEST_CREDENTIAL_FILE.
